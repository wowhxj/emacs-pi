# 队列编辑

## 当前实现

Pi 0.87.1 RPC 的 `queue_update` 只提供 steer 与 follow-up 的文本数组；`clear_queue` 一次清空两栏并返回文本，`steer` 和 `follow_up` 逐条追加。emacs-pi 因此在本地暂存改动，应用时清空并按新顺序重发。队列窗口会随着 Pi 事件更新；暂存改动期间保留本地内容，并提示远端队列是否已变化。

| 队列窗口按键 | 动作 |
| --- | --- |
| `RET` | 在独立编辑区修改消息文本和图片 |
| `M-<up>` / `M-<down>` | 同一栏内上移 / 下移 |
| `s` / `f` | 转为 steer / follow-up，移到目标栏末尾 |
| `d` | 暂存删除 |
| `C-c C-c` | 核对队列后一次应用全部暂存修改 |
| `g` | 放弃暂存修改并刷新 |
| `q` | 关闭窗口；暂存内容留在 buffer 中 |

单项编辑区用 `C-c C-c` 保存到本地队列，`C-c C-k` 放弃；`C-c C-a` 添加 PNG/JPEG 文件，`C-c C-p` 用 `pngpaste` 粘贴剪贴板图片，`C-c C-d` 移除图片，`C-c C-r` 替换图片。保存单项后仍须回到队列窗口按 `C-c C-c`，才会写入 Pi。队列窗口会显示已知图片的预览或文件名。

## 写回边界

emacs-pi 只对能够还原全部原始附件的队列开放写回。对本次 Emacs 会话没有掌握图片数据、重复文本导致附件对应不明、或输入扩展改写后无法对应的消息，界面仍可查看，但应用时会拒绝重排或编辑，以免图片在重发时丢失。带图片的相同文本也不能作为写回目标，因为 Pi 的队列事件没有单项身份信息。

应用前会检查 Pi 当前队列与打开编辑器时的快照。`clear_queue` 返回后再次核对：若期间有消息被消费或新增，暂存修改不会提交，客户端会重发 Pi 实际清出的消息。若某一步 RPC 失败，已确认未发送的消息会存入 `M-x emacs-pi-recover-input` 的恢复列表；超时的消息会标记为发送状态不确定，恢复前应检查队列。运行中的 Pi 仍可能在逐条重发时消费消息，因此顺序无法获得原子保证。若 Pi 在写回时结束运行，重发的消息会留在队列中，直到后续新提示触发处理。

## 后续原生协议

要获得严格的并发安全，Pi 端需要稳定的队列 item ID、修订号，以及单项编辑、移动、删除和附件读取接口。`get_queue` 应返回有序项和 `revision`，`update_queue` 应接收 `expectedRevision` 并在消费队列的同一个序列化边界内完成修改。届时可以替换当前的清空加重发实现，同时保留这套 Emacs 交互。
